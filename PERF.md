# FreeStack Performance Engineering Guide (`PERF.md`)

This document defines the performance budgets, measurement workflow, and engineering rules for adding data, logos, fonts, and dependencies to **FreeStack**.

---

## 1. Performance Budgets (Enforced by `npm run perf:check`)

All production builds are checked against strict resource and runtime budgets on **Mobile (375×812) + Desktop (1280×800)** under **Slow 4G + 4× CPU slowdown**:

| Budget Metric | Target Limit | Current Actual | Enforcement |
| :--- | :--- | :--- | :--- |
| **Home First-Load JS (gzip)** | `<= 150 KB` | **~76 KB** | `npm run perf:check` |
| **Total CSS (gzip)** | `<= 40 KB` | **~11.8 KB** | `npm run perf:check` |
| **Max Single JS/CSS Chunk (gzip)** | `<= 250 KB` | **~76 KB** | `npm run perf:check` |
| **First-Load Data Payload (gzip)** | `<= 100 KB` | **~4.9 KB** (`homeBootstrap.json`) | `npm run perf:check` |
| **Critical Fonts Before First Paint** | `<= 100 KB` | **73.8 KB** (2 Latin variable WOFF2 files) | `npm run perf:check` |
| **Max Single Logo File Size** | `<= 5 KB` (`5,120 B`) | **4,987 B** (`0` files over 5 KB) | `npm run perf:check` & `scripts/build-logos.ts` |
| **Third-Party Runtime Requests** | `0` | **`0`** | CSP `default-src 'self'` + E2E check |
| **Lighthouse Mobile Performance** | `90+` | **96–99** | Playwright / Lighthouse audit |
| **LCP (Slow 4G, 4× CPU)** | `<= 2.0 s` | **0.42 s – 0.68 s** | Playwright trace |
| **CLS** | `<= 0.05` | **0.000** | Fixed `aspect-square` logo boxes + metric-matched font fallbacks |
| **Search Keystroke Latency** | `< 100 ms / key` | **4.2 ms – 14.8 ms** | 150 ms debounce + `startTransition` + server index |

## 2. How to Measure Performance Locally

Never measure performance on the Vite dev server (`npm run dev`). Always build and run the production bundle:

```bash
# 1. Build bootstrap data, client chunks, server bundle, and precompressed (.gz/.br) assets
npm run build

# 2. Verify all bundle, CSS, data, font, and logo budgets
npm run perf:check

# 3. Start the production server
NODE_ENV=production npm run start:prod

# 4. Run the automated E2E & performance verification suite
npm run test:e2e
```

## 3. Rules for Adding Catalog Offers & Data

1. **Never import `/data/offers/**/*.json` in client code**:
   - The 7,881-offer catalog (~19 MB raw JSON) lives on the server and is indexed once at startup by `src/lib/server/offerCatalogIndex.ts`.
   - Client pages use `src/lib/data/homeBootstrap.json` (generated by `scripts/build-bootstrap.ts`) for Home and `GET /api/offers` + `GET /api/offers/:slug` for pagination, search, filtering, and offer details.
2. **Keep Card Projections Compact**:
   - List endpoints (`/api/offers?fields=card`) return compact card projections (`description` capped at 140 chars, top 2 `free_limits`, no `evidence` array or `editorial_notes`) so 48-card pages stay under `~6–8 KB` compressed.
3. **Run Data Validation & Parity Tests**:
   - Always run `npm run validate:data` and `npm test` (including `src/lib/data/dataParity.test.ts`) after modifying catalog items or ranking logic.

## 4. Rules for Adding Logos & Illustrations

1. **Same-Origin Only (`/logos/*`)**:
   - Never hotlink external favicons, Clearbit, Google S2 favicons, or GitHub avatars at runtime. CSP enforces `img-src 'self' data: blob:`.
2. **Strict 5 KB Cap (`<= 5,000 bytes`)**:
   - Every file in `public/logos/` must be `<= 5,000 bytes`.
   - After adding or updating any logo in `public/logos/`, run:
     ```bash
     npx tsx scripts/build-logos.ts
     npm run perf:check
     ```
3. **Use `<OfferLogo />` Everywhere**:
   - Always render offer logos via `<OfferLogo offer={offer} priority={isFirstVisibleRow} />`.
   - `<OfferLogo />` renders a zero-request deterministic initials tile in a fixed `aspect-square` container first, then swaps in the image with `loading="lazy"` (`loading="eager"` + `fetchPriority="high"` for the first row) and `decoding="async"`, preventing layout shift (`CLS = 0`).

## 5. Rules for Fonts & CSS

1. **Self-Hosted Latin Variable WOFF2 Only**:
   - Only `plus-jakarta-sans-latin-wght-normal.woff2` (26.7 KB) and `inter-latin-wght-normal.woff2` (47.1 KB) are preloaded before first paint (`73.8 KB` total).
   - `jetbrains-mono-latin-wght-normal.woff2` uses `unicode-range` in `src/index.css` so it only downloads when a page renders `font-mono` characters.
   - Never import `@fontsource-variable/*` full multi-subset CSS files in `src/main.tsx` (which would bundle 15 font subsets totaling 360 KB).
2. **Scroll & Paint Performance**:
   - Never add `backdrop-filter` (`backdrop-blur-*`) to sticky headers or scrolling containers.
   - Use `.content-visibility-auto` on below-the-fold card grid sections.

---

## 6. Rules for Dependencies & Code Splitting

1. **One-Line Justification**:
   - Any new runtime dependency in `package.json` requires a clear justification and must pass `npm run perf:check` and `npm run audit:prod`.
2. **Route-Level Code Splitting**:
   - Every page outside `HomePage` must be loaded via `React.lazy(() => import('./pages/...'))` in `src/App.tsx`.
3. **Icon Imports**:
   - Never use namespace imports (`import * as Icons from 'lucide-react'`). Import only named icons so Vite tree-shakes unused icons.
